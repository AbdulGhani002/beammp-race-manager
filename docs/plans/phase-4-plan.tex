\section{Races you make and join}

Today a run arms the moment you pick a course, and your time starts the first
time you touch the start line. That is what you called touchy, and you are
right. It is easy to set off by accident.

A race becomes something you make, and other people join.

\begin{enumerate}
  \item You pick a course, the laps and the mode, and you make a race.
  \item You choose \textbf{public}, so anyone on the server can join, or
        \textbf{invite}, and you pick who from the player list.
  \item People join and are put on the grid behind the line.
  \item Nothing is armed. The line does nothing. Sit there as long as you like.
  \item You press \textbf{Start Race}. Only then does the line go live.
  \item Each driver's time starts when they cross the first checkpoint.
\end{enumerate}

The line still starts your own time, which is what keeps the timing fair when
people cross it a second apart. It just does nothing at all until you say go.

\begin{lstlisting}
local lobbies = {}

function RM.lobby.create(pid, d)
  local track = RM.tracks.get(tostring(d.track or ""))
  if not track then return false, "no_such_track" end
  if RM.lobby.of(pid) then return false, "already_in_one" end

  local id = RM.util.shortId()
  lobbies[id] = {
    id      = id,
    host    = pid,
    track   = track.id,
    laps    = math.floor(tonumber(d.laps) or 1),
    mode    = tostring(d.mode or "controller"),
    open    = d.open and true or false,
    state   = "waiting",
    members = { [pid] = true },
    invited = {},
  }
  return true, lobbies[id]
end

function RM.lobby.join(pid, id)
  local l = lobbies[tostring(id or "")]
  if not l then return false, "no_such_race" end
  if l.state ~= "waiting" then return false, "already_started" end
  if RM.lobby.of(pid) then return false, "already_in_one" end

  local key = RM.identity.keyOf(pid)
  if not l.open and not l.invited[key] then return false, "not_invited" end

  l.members[pid] = true
  return true, l
end

function RM.lobby.start(pid)
  local l = RM.lobby.of(pid)
  if not l then return false, "no_lobby" end
  if l.host ~= pid then return false, "not_the_host" end
  if l.state ~= "waiting" then return false, "already_started" end

  l.state = "armed"
  for member in pairs(l.members) do
    RM.race.arm(member, { id = l.track, mode = l.mode, laps = l.laps })
    RM.bus.queue(member, "race.state", RM.race.wire(member))
  end
  return true, l
end
\end{lstlisting}

\section{One grid, one result}

Everyone in the race is placed in a row behind the start line rather than all
on the same spot. The results come out as one table in finishing order, with
the gap to the leader and the gap to the car in front, which is already how the
results screen is built.

Somebody who leaves half way no longer holds up the people still driving. They
are filed as a did not finish and the race carries on.

\section{The pit checkpoint}

A checkpoint can be marked as a pit when you build the course. It is drawn in a
different colour so it is obvious on the map.

A pit is not part of the lap. Driving through it does not count as a gate and
does not skip one. What it does is put you in the pit while you are inside it.

While you are in the pit:

\begin{itemize}
  \item Fuel fills to 100\% instead of adding a quarter.
  \item Repair and Spare tire add nothing to your race time.
  \item The holds still apply in full, and the clock is still running.
\end{itemize}

So a pit stop costs you the time it takes and nothing on top. That is the whole
point of having one.

\begin{lstlisting}
function RM.service.use(pid, d)
  local action = ACTIONS[tostring(d.which or "")]
  if not action then return false, "no_such_action" end
  if jobs[pid] then return false, "already_working" end

  local r = RM.race.get(pid)
  local racing = r ~= nil and r.state == "running"
  local inPit = racing and r.inPit == true

  local hold, cost = 0, nil
  if racing then
    hold = tonumber(RM.config.holds[action.hold]) or 0
    if action.penalty and not inPit then
      local seconds = tonumber(RM.config.penalties[action.penalty])
      if seconds and seconds > 0 then
        RM.race.penalty(pid, seconds, action.penalty)
        cost = seconds
      end
    end
  end

  jobs[pid] = { which = action.name, hold = hold, endsAt = RM.now() + hold,
                cost = cost, full = inPit }
  return true, jobs[pid]
end
\end{lstlisting}

\section{Speed zones between checkpoints}

You asked whether the 37 mph limit could go between chosen waypoints. Yes, and
it is one of the easier things in here.

The checkpoints are already numbered, so a zone is just a start, an end and a
speed. A course can have as many as you like, and they can overlap a pit or
not, as you prefer.

\begin{lstlisting}
zones = {
  { from = 12, to = 14, mph = 37 },
}
\end{lstlisting}

The server already reads everybody's speed for the player list, so it does the
checking. Nothing is trusted to the driver's own game.

Going over the limit does not punish you instantly. You get a warning on
screen, and the penalty only lands if you stay over it, so one bump over a
crest costs nothing. Once it has charged you it will not charge again until you
drop back under.

\begin{lstlisting}
function RM.zones.sample(pid, mph)
  local r = RM.race.get(pid)
  if not r or r.state ~= "running" then return end

  local zone = RM.zones.at(r.track, r.nextGate)
  if not zone then r.overFor, r.overCharged = nil, nil return end

  if mph <= zone.mph then
    r.overFor, r.overCharged = 0, false
    return
  end

  r.overFor = (r.overFor or 0) + (RM.config.rosterMs / 1000)
  if r.overFor >= RM.config.speedGrace and not r.overCharged then
    r.overCharged = true
    RM.race.penalty(pid, RM.config.penalties.speeding, "speeding", r.nextGate)
  end
end
\end{lstlisting}

\section{The spare tire}

I told you this could not be done. I looked again after you said you had seen
it done somewhere, and I was wrong. There is a way.

A flat in this game is two separate things. The air is gone, and some of the
tire is torn. There is no call that mends a tire, which is what I found the
first time and why I said no. But the engine can put air back into a tire, and
the game already does exactly that for the trucks with onboard air compressors.
Every wheel also remembers the pressure it started at.

So the plan is to put the air back and clear the flat, in place, and leave the
rest of the car alone.

\begin{lstlisting}
for _, wd in pairs(wheels.wheels) do
  if wd.isTireDeflated and wd.pressureGroupId and wd.startingPressure then
    obj:setGroupPressure(wd.pressureGroupId, wd.startingPressure)
    wd.isTireDeflated = false
  end
end
\end{lstlisting}

The honest part. This will work for a tire that went flat from a puncture,
which is nearly every flat you get in a race. If a tire is properly shredded
off the rim the game deflates the whole group and changes how it drags, and
that will not come back from air alone. In that case the button falls back to
what it does now, which is the full repair, and it will tell you why.

Because it needs trying in the game and might only cover the common case, this
one sits on its own rather than inside the main phase 4 work.

The tire shop sound goes on the same button. Send me a file if you have one you
like, otherwise I will use one of the game's.

\section{Order of work}

\begin{enumerate}
  \item The pit checkpoint. Small, self contained, useful on its own.
  \item Speed zones. Also small, and it uses the pit work.
  \item Lobbies on the server: make, join, invite, start. All of it testable

is what worked in phases 2 and 3.
