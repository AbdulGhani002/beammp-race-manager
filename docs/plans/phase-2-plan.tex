\section{The one rule this phase turns on}

\textbf{The server clock is the only clock.} Not one timing value comes from
the client. The client reports that it crossed a gate; the server decides when.

That is not caution for its own sake. The client mod ships to every player as a
readable zip, so a lap time the client calculates is a lap time the client can
choose.

The cost is the network round trip. A crossing stamped on arrival gives a
player on 200 ms ping 200 ms of lag in the stamp. Two ways to deal with it, and
the second is better:

\begin{enumerate}
  \item Stamp on arrival. Simple, and it quietly penalises high ping.
  \item The client sends its own frame timestamp alongside the crossing, the
        server keeps a rolling estimate of that player's offset, and corrects.
        The client can still lie, but only inside a window the server already
        believes, and a lie that drifts gets caught.
\end{enumerate}

Going with the second, with the window clamped. Worth writing down now because
it is the single decision the rest of the phase hangs on.
\section{Race state machine}

One race state per player for time trial. Phase 4 turns this into a shared
grid, so the shape is chosen now to survive that.

\begin{center}
\code{idle} $\rightarrow$ \code{armed} $\rightarrow$ \code{running} $\rightarrow$ \code{finished},
\quad or \code{running} $\rightarrow$ \code{abandoned}
\end{center}

\begin{longtable}{@{}lll@{}}
\toprule
\textbf{From} & \textbf{To} & \textbf{On} \\
\midrule
\endhead
idle     & armed     & picks a course, teleports to the start \\
armed    & running   & drives through the start gate \\
running  & running   & crosses a gate, split recorded \\
running  & finished  & crosses the finish on the final lap \\
running  & abandoned & End Race, disconnect, or leaves the level \\
finished & idle      & closes the results \\
\bottomrule
\end{longtable}

\textbf{Penalties only exist in \code{running}.} That is his change, and it
falls out of the machine rather than being bolted onto it.

\section{Splits and laps}

Stored on the server, per run: the course and mode, the lap count and current
lap, start and finish stamps, a split per gate per lap, the missed gates per
lap, and the penalties with their reasons.

Splits are seconds from the start of the run, not deltas. Deltas are a
presentation choice and can always be computed; a stored delta cannot be
recovered into an absolute once a gate is missed.

\section{Missed checkpoints}

A gate is missed when a later gate fires while an earlier one has no split for
this lap. That catches both a deliberate cut and a car tunnelling a gate at
speed.

The penalty is per missed gate, and the reason carries the gate number, so the
breakdown in the results reads as something a person can argue with.

Circuit courses wrap, so gate 1 firing after gate 29 is a lap, not a miss. The
lap boundary is the start gate, which is why the start line is stored
separately from the checkpoint list.

\section{Performance}

Same rules as phase 1, and one new risk. A split is one small message per gate
crossing. Twenty-nine gates against a full grid is phase 4's problem, but the
message shape is decided here, so it is sized for that now: a split is an index
and a number, not a record.

Nothing is recalculated on a timer. A split is computed when a gate fires and
never again. The results payload is built once, when the last driver finishes.

Measured against the phase 1 baseline: \textbf{128 average, 108 one per cent
low}, taken on his server.

\section{Testing}

The mock host gets a clock that can be driven by hand, so a run can be played
through in a test without waiting for real seconds. Cases worth having before
the code is written:

\begin{itemize}
  \item A clean lap. Splits in order, corrected equals dirty.
  \item A missed gate. Penalty logged against the right gate number.
  \item A gate crossed twice. The second crossing ignored.
  \item Gates crossed out of order.
  \item Disconnect mid run. Run abandoned, nothing half written to disk.
  \item End Race mid run. All timing stops at once.
  \item A client reporting a gate it cannot have reached yet.
  \item A client reporting a frame time far outside the believed window.
  \item Two runs on one course by one player. Personal best updates only when
        it should.
\end{itemize}

Then on his server, with two drivers, which is the part that is still blocked.
